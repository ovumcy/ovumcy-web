### Fixed

- **The example stacks now forward every setting the app reads.** The five stacks under `docs/examples/` listed their environment by hand and left out `REGISTRATION_MODE`, `HSTS_ENABLED`, `AUDIT_LOG_ENABLED`, `WEBHOOK_BLOCK_PRIVATE_ADDRESSES`, `REMINDER_SCHEDULER_ENABLED`/`REMINDER_SCHEDULER_HOUR` and the register, logout and calendar rate limits, so a value set in `.env` for any of them changed nothing and a public proxy stack ran with open registration whatever the runbook advised. Each is now passed through with the application's own default, so a stack started as before behaves as before. A repository test reads the settings from the binary's sources and fails when an example omits one without a stated reason.
- **The upgrade steps and the downgrade caveats no longer overpromise.** The runbook and the README now say to take the new compose file, or add the `ovumcy_fence` volume, before the first v2.0.0 start: without it every armed calendar feed is disarmed on every start. The downgrade section gains the case a release older than v2.0.0 can reopen (delete the fence volume before upgrading again), and the statements that nothing revoked can return, that a pre-041 binary refuses to start, and that migrations 032/034/035 need nothing in either direction are corrected.
