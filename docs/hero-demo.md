# Hero Demo Asset Pack

This document defines the privacy-safe hero demo pack for Ovumcy.

The goal is to keep one reusable asset set for README screenshots, release notes, and short walkthrough clips without ever relying on a live public instance.

The pack is the six stills listed under Asset Guidance below — `docs/screenshots/` also holds logo and social-preview art that is not part of it — plus the recorded first-run clip `docs/demo.gif`, which the README embeds as its hero. The repository carries the stills and the GIF. The clip's other encodings — `docs/demo.mp4` (H.264, its source copy), `docs/demo.webm` (VP9) and `docs/demo-poster.jpg` (its first frame), which the project website embeds — are written next to it but ignored by git, and so are the generators: `scripts/take-screenshots.mjs` writes all six stills, `scripts/record-demo.mjs` writes the clip in all four forms, and both share `scripts/demo-runtime.mjs`. They are maintainer tooling kept outside the published tree; the Capture Checklist below describes what they do, so the pack can be regenerated by hand or by an equivalent script, and the privacy review they cannot do for you.

## Core Flow

Use these assets in this order when building a short walkthrough or landing-page demo:

1. Register: [`docs/screenshots/register.jpg`](./screenshots/register.jpg)
2. Dashboard: [`docs/screenshots/dashboard.jpg`](./screenshots/dashboard.jpg)
3. Calendar: [`docs/screenshots/calendar.jpg`](./screenshots/calendar.jpg)
4. Settings and export: [`docs/screenshots/settings-export.jpg`](./screenshots/settings-export.jpg)
5. Mobile install prompt: [`docs/screenshots/install-prompt.png`](./screenshots/install-prompt.png)
6. Dark theme: [`docs/screenshots/dark-theme.jpg`](./screenshots/dark-theme.jpg)

This sequence matches the current product story: create an account, log today quickly, review the month, export or tune settings, install the app on a phone home screen, then show the dark theme option.

## Privacy Rules

- Never capture a live public deployment.
- Use a local or otherwise private self-hosted instance only.
- Use seeded sample data and generic identity values.
- Avoid real email addresses, real notes, and any personal health history in captures.
- No credential may be legible in any frame: passwords stay in masked fields, and the recovery code shown after sign-up is blurred in the clip even though the account is throwaway.
- Every frame that shows a prediction also shows its estimate qualifier and the "not medical advice or a method of contraception" disclaimer.
- Keep the install-prompt asset synthetic and local; it is driven by the same browser event simulation used in `e2e/pwa-install.spec.ts`.

## Asset Guidance

The still half of the pack is intentionally static-first:

- `register.jpg` (1280×800 JPEG) covers the first-run entry point.
- `dashboard.jpg` (1280×800 JPEG) covers the primary daily logging surface: the cycle ring and ribbon (both views, the default) with their estimate qualifiers and disclaimer, and today's journal.
- `calendar.jpg` (1280×800 JPEG) covers month review and cycle context; it is scrolled so the prediction disclaimer under the grid is in frame.
- `settings-export.jpg` (1280×800 JPEG) covers data ownership and export.
- `install-prompt.png` (390×844 PNG) covers phone install CTA behavior, on `/login`.
- `dark-theme.jpg` (1280×800 JPEG) covers the dark theme option, on the dashboard.
- `demo.gif` (720×450) covers the first-run flow in motion; it is the one recorded asset, and every privacy rule in this document applies to it exactly as to a still. It stays within the size of the GIF it replaced (about 4.8 MB).

For short release clips or social cuts, prefer stitching these assets together over recording a live server session unless a release specifically needs motion.

## Capture Checklist

When regenerating the pack:

1. Boot a throwaway instance from the current tree the way the e2e harness does — `go run ./cmd/ovumcy` on a fresh SQLite file with a per-run `SECRET_KEY`, `DEFAULT_LANGUAGE=en`, `TZ=UTC` — and delete its database afterwards. Both scripts do this themselves; they need Go and Playwright's chromium, and the recorder also needs an ffmpeg with libx264 and libvpx-vp9 on `PATH` (or `FFMPEG=<path>`).
2. Register `demo@example.com` with a password generated for the run, confirm the recovery code without reading it out, and finish cycle setup with the last period starting 15 days ago.
3. For the stills, restore about three months of synthetic history through **Settings → Restore from backup**: three completed 28–30-day cycles, period days with flow, mood and a few built-in symptoms, no notes and no custom symptoms. Then log today's mood and a symptom on the dashboard.
4. The mobile install prompt on `/login`: a 390×844 mobile viewport and a synthetic `beforeinstallprompt` event.
5. The dark theme surface: switch the theme under **Settings → Interface** and save, then open the dashboard.
6. The clip records the first-run flow on a fresh account at 1280×800: sign-up, cycle setup, logging today's mood and symptoms, the calendar, and the dark theme. It is encoded to H.264 MP4 and VP9 WebM without audio, a JPEG poster of the first frame, and a palette GIF scaled to 720×450 whose frame rate steps down until it fits the size budget.
7. Review every frame for accidental PII, legible credentials, and a prediction shown without its qualifier and disclaimer before publishing — the GIF frame by frame, not only the stills.
